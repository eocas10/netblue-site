El hash es una huella de una sola vía: de la clave sale el hash, pero del hash no se regresa a la clave. Valores de ejemplo.

Lo que se lleva

ana.rivera: 8c1f…e42a
luis.ortiz: 5e88…1d15
carla.gomez: 8c1f…e42a
jose.diaz: b7a2…90cf

No ve ninguna clave. Pero dos usuarios con la misma clave tienen el mismo hash.

La tabla que trae

123456 → e10a…883e
password → 5e88…1d15
qwerty → d857…3a5f
Verano2026! → 8c1f…e42a
y millones más

Alguien ya hizo el cálculo una vez. La tabla arcoíris guarda ese trabajo comprimido para reutilizarlo.

Lo que sigueEntra a esas cuentas y prueba las mismas claves en otros sitios.

Cómo protegerse

  • El sitio: añadir una sal única a cada clave antes del hash
  • El sitio: usar funciones lentas hechas para claves (bcrypt, scrypt, Argon2)
  • Tú: usar frases largas y únicas
  • Tú: no repetir claves entre sitios
  • Tú: activar MFA
  • Tú: cambiar la clave de inmediato si el sitio sufre una filtración
Con sal, la misma clave produce un hash distinto para cada usuario y la tabla precalculada deja de servir.

Los seis pasos

  1. El hashEl sitio guarda una huella de tu clave, no la clave.
  2. El robo de la baseEl atacante se lleva los hashes de todos los usuarios.
  3. La tabla precalculadaTrae millones de claves con sus hashes ya calculados.
  4. La búsquedaBusca cada hash robado en la tabla y obtiene la clave original.
  5. Las claves reveladasCaen las claves comunes; las largas y únicas no están en la tabla.
  6. La defensaSal única y funciones lentas en el sitio; frases largas, claves únicas y MFA de tu parte.
